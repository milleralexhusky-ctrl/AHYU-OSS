# AHYU 4.35.1：行为画像面板

versionCode 621。

## 起因

4.35.0 开始每条请求都记质量档，但只能在命令行里用 awk 查。
数据有了，看不见，等于没有。

## 改动

### 新增 `QualityStats`

和 `Usage.summary` 分开：那个算"用了多少、多快、多少钱"，
这个算"靠不靠得住、工具用不用得起来"。两块分开，免得为了加画像
去动已经稳定的统计逻辑。

聚合两个维度：

- 按渠道：样本数、可用率、空回、截断、跑题、重发、工具失败率
- 按模型：样本数、可用率、工具失败率

**口径说明**（写进 UI 提示，避免误读）：

- 可用率 = `ok` / **有质量标记的样本**。旧行没有第 18 列，不算分母——
  否则会把"没记录"算成"不可用"。
- 工具失败 = 给了工具定义但没吐结构化调用的比例。`—` 表示这个渠道
  没有带工具的样本，不是 0。

## 验证

真机 4.35.1 / 621 安装运行。用当时累积的 4 条带标记样本复算：

```
渠道          样本  可用率  空回  截断  跑题  重发  工具失败
WorkBuddy 1   3     100%    0     0     0     0     0%
WorkBuddy 2   1     100%    0     0     0     0     0%
```

口径正确。样本量还小（4.35.0 才上线），正常用几天会自己填满。

## 现在能回答的问题

不再需要构造测试或写 awk：

- 哪个渠道最靠得住（可用率排序）
- 哪个渠道经常空回复（空回列）
- 哪个模型给了工具却不调（工具失败率）
- 哪个渠道被截断得多（可能是 max_tokens 配置问题）
- 哪个渠道用户总在重发（retry 列，最真实的差评）
