# AHYU 4.33.0：观测层补全

版本 4.33.0 / versionCode 614。

## 起因

想弄清"模型的工具调用逻辑"，前提是观测闭环。盘点代码后发现记录层有三处硬缺口：

1. **探活混进真实流量**：2488 条（占 34%）是 2~22ms 的本地即拒，不是对话，
   全被记成 ok=0。今天还有 22 条。以前靠"渠道名为空"在 Stats 里跳过它们，
   是运气不是设计。
2. **工具调用不可见**：旧数据里"结构化调用""正文里的文本调用""什么都没说"
   三者全都表现为「工具=0」，而这三件事含义完全相反。
3. **日志不落盘**：Log 只有内存 500 条环形缓冲，重启即清空。想翻 21:24 那次
   失败时，一条都没有了。

## 改动

### 1. usage.tsv 从 12 列扩到 17 列

新增第 13~17 列：

| 列 | 内容 | 取值 |
|---|---|---|
| 13 | 来源 | user / probe / unknown |
| 14 | 工具数 | 本次请求带了多少个工具定义 |
| 15 | 响应形态 | native / text / empty / error / plain |
| 16 | 解析结果 | none / ok / fail / fixed / dropped |
| 17 | 工具史 | 历史里是否已含工具调用/结果（0/1） |

`Usage.Obs` 承载这组观测。判定逻辑在 `Server.shapeOf()`：
响应失败→error；有结构化调用→native；无字符→empty；正文像调用→text；否则 plain。

### 2. 日志落盘

`Log.add()` 增加 `toDisk()`：攒批追加写到 `files/eta-gateway.log`，
64 行或 5 秒落一次，超 4MB 滚成 `.1`（只留一份）。写盘失败保留缓冲不丢。

## 验证（真机 4.33.0 / 614）

| 场景 | 记录结果 |
|---|---|
| 带 1 个工具，首轮 | 工具数=1 形态=native 解析=none 工具史=0 |
| 带工具 + 已有工具历史 | 工具数=1 形态=native 解析=none 工具史=1 |

日志落盘确认：`eta-gateway.log` 4038 字节，含实时记录。

## 顺带发现

落盘日志里直接给出了之前一直靠猜的那条线索：

```
[WARN] trae 本轮没有产生任何内容，原始流可能换了结构
```

这是 Trae 通道自己打的警告 —— 它明确表示原始流结构可能有变。
在日志落盘之前，这条信息每次重启就消失了。
