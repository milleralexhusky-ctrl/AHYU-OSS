# AHYU 4.35.0：结果质量判定

versionCode 620。

## 起因

17 列记录全是传输和形态描述，**没有一列判断"这次回答本身行不行"**。
而"完全理解"不可能靠穷举测试——每测一个点都是一次真实请求和一次额度消耗。

出路是让**日常真实流量自己变成样本**：不用构造测试用例，只要每个请求
结束时能机械判一下"这个结果能不能用"。

## 判据

只取结构上可机械判断的四条，不碰语义：

| 判定 | 依据 | 说明 |
|---|---|---|
| `empty` | 输出为空 | 最确定的失败 |
| `cut` | `stopReason=length` | 上游明说被截断，硬证据 |
| `off` | 输出与请求零重叠 | 近似判"答非所问"，宁可漏判 |
| `retry` | 用户 60 秒内重发同一条 | 最真实的"用户觉得不行" |
| `ok` | 以上都不成立 | |

**为什么不做语义质量判断**：那需要品味，写不进代码；判错比不判更糟，
会污染后续所有基于它的分析。

**关键修正**：有结构化工具调用时，正文为空是**正常**的（模型直接给调用），
不能判成 `empty`。为此 `judge()` 加了 `sawToolCall` 参数，
否则所有纯工具调用都会被误标为失败。

## 改动

- 新增 `Quality`：判定逻辑 + 零重叠检测（抽 2 字片段，抽 12 个，全不中才判跑题）
- `Repeats.seenCount()`：返回窗口内的原始重发次数。
  `check()` 只在超过容忍次数时返回非空（用来拦），这里要的是第 2 次就记。
- `Usage.Obs.quality` → `usage.tsv` 第 18 列
- `Server.lastUserText()`：取最后一条用户消息，供跑题判定对照

## 验证

离线单测 8 项全过：

- 放行：正常回答、中文短答、工具调用
- 拦下：空输出、空白输出、被截断、跑题（"17×23"答成"社交媒体用户ID"）、用户重发

真机验证（4.35.0 / 620）：

| 场景 | 记录 |
|---|---|
| 正常对话 | 形态=plain 质量=ok |
| 工具调用（正文为空） | 形态=native 工具=1 字符=0 **质量=ok** |

工具调用那条确认了修正生效——不会被误判成 empty。

## 意义

从这一版起，`usage.tsv` 里每一行都能回答"这次结果能不能用"。
配合已有的 17 列（来源/工具数/形态/解析/工具史），
**日常流量自动成为样本**，不必再为理解模型行为而穷举构造测试。

下一步可以用这批数据做：按渠道算可用率、按请求类型算失败模式、
找出"给了工具却不调"的模型——全部不再需要额外发请求。
