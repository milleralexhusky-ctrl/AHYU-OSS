# AHYU 4.40.0：HTTP 请求回放 + 首次引导 + 可用性动作

versionCode 633。4.39.0 的延续：再把请求侧纳入回放测试，并补三个日常体验点。

## 一、HTTP 请求回放测试（自检 24 项）

新用例直接把固定字节喂给 `Server.readRequest`：

| 断言 | 防的回归 |
| --- | --- |
| chunked 正文里「你」被块边界切成两半 | 4.37.0 修过的 U+FFFD 问题 |
| `0` 块后的 trailer 读到空行 | trailer 残留会让 keep-alive 下一个请求错位 |
| 同一连接上的第二个请求仍能解析 | 上面两条的端到端结果 |
| 单块 9MB 被拒绝 | 绕过 Content-Length 的 chunked OOM |

写这条测试时第一版把裸 `ByteArrayInputStream` 传进去，第一次 `readRequest`
新包了一层 `BufferedInputStream`，把预读到的第二个请求一起丢了——测试自己
报了「第二个请求丢了」。真实 Server 复用外层缓冲，所以这是测试写法的问题；
改成复用同一个 `BufferedInputStream` 后通过。这条弯路本身也说明：
**测试要按真实调用形态写，否则测的是另一个东西。**

## 二、首次使用引导

一个账号都没有时，首页出现「第一次使用」卡片：

1. 添加一个账号（账号登录 / API Key / 中转站）
2. 点「启动网关」
3. 把地址和 Key 填进客户端

加完账号回到首页会自动重建、撤掉卡片。老用户完全看不到。

## 三、暂不可用账号页：下一步动作

每一行新增：

- **复制**：把账号名 + 原因复制出来（发给支持/自己留存）；
- **重登**：原因是凭证/登录/过期/401 时，直接打开该渠道的登录页，
  不再要求先点进详情页自己找入口。

登录返回后页面自动重建，状态不会停在旧的。
