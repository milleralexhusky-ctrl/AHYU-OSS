# 4.51.1 — 上游回空、账号限制与重复 /v1

## 起因

客户端反馈集中在三件事：

1. 用 Anthropic Messages 接入时，模型有时回一条**空回答**；客户端会显示“重连失败”，
   甚至一直重连。
2. WorkBuddy 账号被上游判定“异常行为，已被限制使用”（HTTP 403 / code 11140），
   网关仍逐个模型重试、探活，日志里刷出几十条 403。
3. 有些 SDK 会在 Base URL 后面再拼一次 `/v1`，实际请求变成 `/v1/v1/models`，
   网关只回 404，用户以为“账号加不进去”。

## 改动

### 上游回空不再当成功

- 新增 `EmptyUpstream`：上游 HTTP 200 / 正常结束，但没有任何正文、思考或
  工具调用。以前这种流会被写成 200 空回答；现在：
  - 非流式：换下一个候选；全部为空时返回 **502 + “上游没有返回任何内容，请重试”**；
  - OpenAI 流式：`Streamer.finish()` 在没有内容时不再写 finish/[DONE]，
    DeferredWriter 尚未提交，可以直接换候选；
  - Anthropic 流式：`message_start` 改为**延迟到第一段内容才写**，空流不提交，
    因此也能换候选；已经出过内容才按“无法换号”处理。
- `FailScope` 把 `EmptyUpstream` 归为 `TRANSIENT`：换号/换模型有意义，
  不把账号记成坏号。

### Anthropic 协议的虚拟模型真正轮换

`auto*` 在非 OpenAI 协议上以前只解析成**一个**具体模型再走 `pickAll`，
等于把多模型轮换退化成单模型重试。现在和 OpenAI 路径一致，直接用
`Router.candidates()` 的候选列表：可以跨模型换，某个模型回空/被限就试下一个。

### 账号被上游限制（WorkBuddy 11140）

- 识别 `11140 / has been restricted / unusual activity / 异常行为`：
  标记整个账号为“限制”，**退出派发与探活**，写一条 ERROR 日志并在账号上留说明；
  6 小时后自动允许再试一次。
- 不再对受限账号的几十个模型逐个重试，避免继续放大“异常活动”证据。
- 用户在账号编辑器里保存/重新登录时清除限制标记，立即重新验证。

### 重复 /v1 与反斜杠路径

`Server.normalizePath()` 收掉 `/v1/v1/...` 这类重复前缀，并把反斜杠当分隔符容错：
Base URL 填 `http://127.0.0.1:8321/v1` 的客户端再拼 `/v1/models` 也能正常返回目录。

## 验证

- 真机自检 36 / 36 通过（新增 `/v1/v1/models` 与反斜杠规范化断言）。
- `GET /v1/v1/models` → 200。
- 对一个已知回空的模型：`/v1/messages` 与 `/v1/chat/completions` 都返回
  **502 + 明确原因**，不再是 200 空回答。
- Anthropic `auto` 流式请求能从空候选换到有内容的模型，
  事件序列仍是 `message_start → content_block_* → message_stop`。
- WorkBuddy 403/11140 首次出现即标记受限，日志只报一次，后续请求不再打上游。

## 未做 / 说明

- WorkBuddy 的账号限制是上游判定，网关无法解除；需要用户在官方客户端申诉或换号。
- Trae 的部分 agent 请求仍可能回空（上游行为），现在会被识别并换候选，
  不再伪装成成功；如果所有候选都空，客户端会收到明确的 502。
