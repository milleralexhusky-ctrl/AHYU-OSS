# AHYU 4.29.13 — 账号详情页能回答"为什么这个号只有 500"

## 起因

用户问："WB5 是国行版，为什么只有几百积分，而不是和 WB1/WB2 一样几千？"
界面当时只有一个 `积分` 数字，谁也答不了；查上游账单才发现真实原因是
**WB5 一共领了 7527、用掉 7027**（57 张包只剩那张没动的体验版 500），
而 WB1/WB2 各领 3531/3533、只用掉 1500 上下。数字本身没错，是**缺了构成**。

## 实现

- `core/WbTasks.packs(provider)`：解析 `POST /v2/billing/meter/get-user-resource`
  里的 `Accounts[]`，逐包给出 `{name, remain, size, used, end}`（金额用
  `CapacityRemainPrecise` / `CapacitySizePrecise` 优先，退回落整数列），
  兼容 `data.Response.Data` 与 `data.Data` 两种包装。
- 账号详情页（仅 `type == workbuddy`）新增「额度构成（上游账单）」卡片：
  点「查询额度明细」后台拉一次，渲染成
  `● 包名  剩 X/Y（已用 Z）  到 2026-11-12`，按剩余降序，
  已用完的包最多列 8 条，顶部一行 `合计剩余 N credits · 共 M 个包`。
- 只读：`get-user-resource` 是查询接口，不改服务端状态。

## 真机验证（4.29.13）

直接调 `WbTasks.packs()` 对 WB1 走真实上游：

```
合计回到 20 个包；首包 {"name":"CodeBuddy个人体验版","remain":500,"size":500,
  "used":0,"end":"2026-10-31 23:59:59"}；
以及 "剩余1500→已用1500、到 2026-10-18"（就是那张先用完的裂变包）
```

解析结果与之前用 Python 直连上游算出的数字一致（WB1 剩余 2031、WB5 剩余 500）。
自检 19/19，`/health` 401（活着），版本 `4.29.13`（versionCode 579）。
