# AHYU 文档索引

这个目录保存**改动依据**，不是 API 手册。代码里的大型决策都带着注释，
但"为什么改、当时看到了什么现象、怎么验证的"留在版本记录里。

## 目录

| 路径 | 内容 |
| --- | --- |
| [`changelog/`](changelog/) | 从 4.20.0 起的逐版本记录。按版本号顺序读最近十份即可接手 |
| [`notes/`](notes/) | 跨版本的真机验证记录与专项笔记（保活等） |
| [`research/`](research/) | 调查上游协议时写的一次性 Python 脚本，保留作证据 |

## 怎么读

1. 先看根目录 [`README.md`](../README.md) 了解项目定位与构建。
2. 再看 [`changelog/README.md`](changelog/README.md) 的版本索引，挑与你问题相关的版本。
3. 排查线上问题时，按"现象 → 最近动过的版本 → 对应记录里的验证方式"倒推。

## 记录约定

- 文件名：`AHYU-<版本号>-<一句话主题>.md`
- 每份记录至少写清楚：**起因**（看到了什么现象/数据）、**改动**、**验证**（真机还是离线）。
- 没验证的部分单独写在「未做 / 遗留 / 尚未证实」，不要混进结论里。
- 一次性补丁脚本、历史备份不要放回根目录；需要留证据的放 `research/`。
